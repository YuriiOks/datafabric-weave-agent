What changed

In this version of the page.
  • Clickable prototypes instead of screenshots. Each example is a working prototype with a Desktop and Phone switch and a Full screen button. The Rendered and Markdown toggle, On this page, Copy, the Relations tile and the related cards all work, and Alpha Ticket Helper, Epsilon Triage Agent and Delta Wiki MCP open each other.
  • Same design. The page design is unchanged from the last version, including Related components in the right column on desktop.
  • Page navigation and collapsible sections. A navigation list on the right follows your scroll (a dropdown on a phone). Each section opens and closes, and Expand all and Collapse all are at the top.
  • Prod only. Only Prod is ingested from the GroupAI platform, because components that are not tested must not be recommended. Those components get a small Prod pill next to Eligible.

Skill page

Alpha Ticket Helper, a skill from the GitHub skills repository. The reference example for the design.

On a wide screen: the facet band hero, four state tiles, then two columns. The Definition is on the left. On the right are the eligibility card, the Source card and, under it, the related components as stacked Registry cards. Below 900 px it becomes one column: hero, an Eligible and Recommend row, the grouped table, the Source block, the Definition and the related cards. Use the Desktop and Phone buttons to switch, or open it full screen.

Reuse and size

What the app already has, and what is new to build.

Size L

Cost to port

Reuses from the app

  • PlaybookHero title pattern (lead and accent words)
  • FacetBand, drawn full width and 90 px tall
  • StatCardEnhanced, with the progress ring switched off and the top border set by state
  • ComponentCard, compact 72 px variant
  • cardStyles id pill and type pill
  • antd Table, Tag and Alert

New to build · size L

  • MarkdownViewer: Rendered and Markdown toggle, frontmatter card, On this page list, copy buttons, alert callouts, tables (size M by itself; cheaper if the app already has a markdown renderer)
  • SourceBlock with the Prod pill and Open source link (S)
  • DetailHero and the two-column page, with the right column holding eligibility, Source and the related cards (S)
  • Breakpoint switch at 900 px between the two layouts (S)
  • Phone-only Eligible and Recommend row, and the grouped table (S)
  • RelationStrip (compact cards) with the "None recorded" state and the withheld-declaration warning, shared by both layouts

Open questions

  • Should the four tiles come back on a phone as a 2 by 2 grid under the hero? They are left out because the mobile pick had none.
  • The hero band is 90 px tall on a wide screen and 75 px on a phone. Say if it should be taller or shorter.
  • Rendering both layouts and switching with a media query is the simplest build. Reflowing one layout is possible but needs the Source card and eligibility card to move in the DOM.
  • With several related components, the right column grows long next to the Definition. Say if the cards should collapse after three.

Coverage check

Every field of today’s page, accounted for in the prototypes on desktop and on phone, for all three component types.

Wide layout

  • Back to registry link above the hero
  • Hero: band, red id pill, type pill, title with red last word, version and tenant line
  • Tiles: Version, Source, Relations, Quality flags, with the state legend
  • Definition: file path, Open source, Rendered and Markdown toggle, frontmatter, On this page, full .md, code block with Copy, callouts
  • Details: Triggers, Version, Native binding, Tenants, Quality flags
  • Right column, top: Eligible, the Recommend button
  • Right column, middle: Source with origin, environment, file path, revision, last synced, pulled by, Source, Source reference, External ids, Catalogue version, Open source
  • Right column, bottom: Related components as stacked Registry cards: Used by, Uses and Depends on, with "None recorded" and "1 unresolved declaration withheld" (the Relations tile scrolls to it)
  • Component id is the hero id pill; description, tools and tags are in the frontmatter card

Phone layout

  • Back to registry link and the same hero
  • Eligible (and the Prod pill for Prod) with a full-width Recommend button
  • Grouped table: Component id, Description, Triggers, Tools, Tags, Version, Native binding, Tenants, Quality flags
  • Source block with every provenance field and Open source
  • Full-width Definition with the same toggle, frontmatter, list, copy button and callouts
  • Related components as stacked cards: Used by, Uses ("None recorded"), Depends on with the warning
  • Code blocks, tables and the raw .md scroll inside their own box; the page itself does not scroll sideways
  • Stat tiles are not shown on a phone; the On this page list starts collapsed

Prototype interactions

  • Desktop, Phone and Full screen (Esc or Close to leave)
  • Rendered and Markdown toggle, On this page links and its collapse, Copy with a "Copied" confirmation
  • Relations tile scrolls to Related components
  • Related cards open Alpha Ticket Helper, Epsilon Triage Agent and Delta Wiki MCP, with a Previous component button; the other two cards show a note
  • Back to registry, Recommend for a need like this and Open source show a note describing what they would do
  • Hover and keyboard focus states on cards, buttons and links
