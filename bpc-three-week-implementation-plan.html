Three-week implementation plan

BPC delivery in three weeks.

04

Capability gates and import path

Planning records a delivery sequence. It does not create issues, resolve bank identities, or authorise an unqualified capability.

1

Read the pack

Select one calendar profile and read its manifest and task briefs.

2

Resolve Jira preflight

Resolve project metadata, assignee identities, hierarchy and permitted fields before an import action.

3

Plan the actions

Prepare the create-or-reconcile map using the selected profile, resolved fields and stable task markers.

4

Upsert idempotently

The workstation agent creates missing items and reconciles existing ones from the resolved map, preserving unrelated content.

5

Read back the result

Read every touched issue back: parent, assignee, dates, estimates and dependency links. Report mismatches; preserve issue status.

G0 — proven reuse before estimates become commitments

CORE-01 verifies the current bank implementation map and the intended reuse boundary before dependent implementation starts. A local proof of concept remains an estimate condition, not proof that every reuse path is available.

Foundation acceptance — contracts and evidence

Complete the selected foundation task contracts and their recorded dependencies. Parent story progress is evidence only; it does not automatically close a recommendation parent.

Extension acceptance — separate scope and quality decision

Confirm the lexical-baseline scope and the quality evidence required by each affected parent. This plan does not authorise a full LLM, embedding or graph-boost recommender.

05

Scope, assumptions and open control points

The concise plan leaves technical detail in the task briefs and names the conditions that still need an accountable decision.

In the default plan

Shared graph and source work, bounded refresh, existing Hub hardening and the current three parent delivery tracks. Existing Postgres and FalkorDB stay in place.

Only in the extension

Three-type lexical recommendation baseline work, scheduled only once scope is confirmed. This is deliberately smaller than a future engine programme.

Still unresolved

Jira assignee identifiers, epic key and import schema; current bank file map; availability; scope authority and recommendation quality acceptance.
